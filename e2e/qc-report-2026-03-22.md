## Issues Found

### HIGH

| # | Description | Location | Fix Suggestion |
|---|-------------|----------|----------------|
| H1 | **Flow gap: Draft auctions have no Submit action**. After item approval, the auction stays in Draft with only a "View" button. Seller cannot advance auction from Draft → Approved. The "Gửi duyệt" (Submit) button was removed per stakeholder request, but now there's no way to submit the auction. | `MyListingsPage.tsx` auction actions | Either: (a) add Submit button back for Draft auctions whose item is Approved, or (b) auto-submit auction during `/sell` wizard after item creation, or (c) add a "Submit & Set Timing" combined action |

### MEDIUM

| # | Description | Location | Fix Suggestion |
|---|-------------|----------|----------------|
| M1 | **i18n fallback to English on /sell page**. All text shows English ("Create New Auction", "Item Info", "Next") instead of Vietnamese. The `sell.*` namespace keys exist in `vi/common.json` but aren't being picked up — likely the i18n namespace isn't loaded or the keys are under the wrong path. | `CreateAuctionWizardPage.tsx`, `GuidedImageUpload.tsx` | Verify `sell.*` keys in `vi/common.json` are at the correct nesting level. Check if `useTranslation()` needs a namespace param. |
| M2 | **Validation messages in English** ("Please enter item title" instead of Vietnamese). The component uses `t('createItem.titleRequired')` which should resolve to Vietnamese, but shows English. Same root cause as M1. | `CreateAuctionWizardPage.tsx:L250` | Same fix as M1 |
| M3 | **Sidebar shows "+ List Item" in English** instead of "+ Đăng vật phẩm". The `nav.sell` key may not exist in the Vietnamese locale, or i18n is defaulting to English. | `buildMenuItems.tsx:L179` | Verify `nav.sell` key exists in `vi/common.json` under `nav` object |

### LOW

| # | Description | Location | Fix Suggestion |
|---|-------------|----------|----------------|
| L1 | **Items tab race condition**: Initially shows "Items (0)" then updates to "Items (12)" after switching tabs. The `useMyItems` query loads asynchronously and the tab label renders before data arrives. | `MyListingsPage.tsx` tab labels | Use loading state or show spinner until data loads |
| L2 | **Category field appears late**: On Step 0, Category field is hidden initially (categories haven't loaded) then appears after validation triggers. Minor visual shift. | `CreateAuctionWizardPage.tsx` conditional render | Always render the field with a loading placeholder, or use `isLoading` from `useCategories()` |
| L3 | **Ant Design deprecation warnings in console**: `[antd: message] Static function`, `[antd: Alert] message is deprecated`, `[antd: InputNumber] addonAfter`. Not user-facing but indicates upcoming breaking changes. | Multiple components | Migrate to Ant Design v6 recommended patterns (App.useApp(), use `description` prop) |

## Verdict: PASS WITH NOTES

The create item + auction flow works end-to-end (seller creates via /sell → admin approves → auction visible in My Listings). However, there is a **critical flow gap (H1)**: after removing the Submit button from Draft auctions, sellers have no way to advance their auction from Draft → Approved → Scheduled. This needs to be resolved before the flow is production-ready.

The i18n issues (M1-M3) are cosmetic but affect the Vietnamese user experience — all `/sell` page text shows in English instead of Vietnamese.
